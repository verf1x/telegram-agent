# Техническое задание
## Telegram-бот для взаимодействия с Codex

**Версия:** 1.0 (MVP)  
**Тип документа:** Функциональные требования заказчика  
**Платформа:** Telegram  
**Технология разработки:** TypeScript

---

## 1. Общее описание

Необходимо разработать Telegram-бота, предоставляющего интерфейс для взаимодействия с AI-агентом Codex.

Бот должен работать на локальном компьютере владельца и позволять нескольким авторизованным пользователям одновременно взаимодействовать с агентом через Telegram.

В качестве AI-движка используется установленный на компьютере Codex с авторизацией через ChatGPT, без отдельного OpenAI API.

Основное назначение продукта — удобное общение с AI-агентом для решения учебных и повседневных задач с поддержкой математических формул, программного кода и структурированного текста.

Разработка должна выполняться поэтапно. На первом этапе необходимо реализовать минимальную, но полноценно работающую версию продукта.

## 2. Функциональные требования к MVP

### 2.1. Общение с AI-агентом

Пользователь должен иметь возможность:

- Отправлять текстовые сообщения боту.
- Получать ответы от Codex непосредственно в Telegram.
- Вести последовательный диалог с сохранением контекста.
- Задавать уточняющие вопросы, ссылаясь на предыдущие сообщения.
- Начинать новый диалог со сбросом текущего контекста.

Бот должен сохранять контекст диалога между перезапусками приложения.

Во время обработки запроса пользователь должен видеть, что агент формирует ответ.

В случае ошибки или временной недоступности агента пользователь должен получать понятное уведомление.

### 2.2. Форматирование сообщений

Ответы агента должны поддерживать расширенное форматирование Markdown, включая:

- Заголовки.
- Жирный и курсивный текст.
- Маркированные и нумерованные списки.
- Цитаты.
- Гиперссылки.
- Таблицы.
- Встроенный программный код.
- Многострочные блоки кода.
- Математические выражения в формате LaTeX.

Необходимо поддерживать как формулы внутри текста, так и отдельные математические блоки.

Математические выражения должны отображаться в отформатированном виде, насколько это позволяют возможности Telegram.

Длинные ответы должны передаваться полностью, без потери текста и нарушения порядка сообщений.

Если определённый формат не поддерживается клиентом Telegram, необходимо предусмотреть читаемый альтернативный вариант.

### 2.3. Многопользовательский режим

Бот должен поддерживать работу нескольких пользователей.

Требования:

- Каждый пользователь общается с агентом независимо от остальных.
- У каждого пользователя собственная история и контекст диалога.
- Сообщения разных пользователей не должны смешиваться.
- Пользователи не должны иметь возможности просматривать чужие диалоги.
- Сброс диалога одним пользователем не должен влиять на остальных.
- Одновременная работа нескольких пользователей не должна нарушать целостность их диалогов.
- Диалоги должны сохраняться после перезапуска бота.

В MVP у каждого пользователя должен быть один активный диалог. Возможность создавать несколько диалогов для одного пользователя будет добавлена на следующем этапе.

### 2.4. Авторизация и управление доступом

Бот должен быть приватным. Использовать его могут исключительно пользователи, получившие личное одобрение владельца.

**Владелец бота является администратором и самостоятельно определяет, кому разрешено пользоваться сервисом.**

Предусмотреть следующий сценарий:

1. Новый пользователь открывает бота в Telegram.
2. Отправляет запрос на получение доступа.
3. Администратор получает уведомление с Telegram-юзернеймом пользователя и его идентификатором.
4. Администратор может одобрить или отклонить запрос.
5. После одобрения пользователь получает доступ к общению с агентом.
6. В случае отказа пользователь не получает доступ к функциональности бота.

Администратор должен иметь возможность:

- Просматривать список разрешённых пользователей.
- Одобрять новые заявки.
- Отклонять заявки.
- Отзывать ранее выданный доступ.
- Определять пользователя по его Telegram-юзернейму.

Разрешения должны сохраняться после перезапуска приложения.

Изменение Telegram-юзернейма не должно приводить к потере доступа или позволять другому человеку воспользоваться чужим разрешением.

**Администратор управляет доступом, но административные функции не предполагают просмотра личных переписок других пользователей.**

### 2.5. Управление диалогом

Предусмотреть базовые команды или другие удобные элементы управления для:

- Начала работы с ботом.
- Получения справки о возможностях.
- Сброса текущего диалога.
- Просмотра состояния агента.
- Отправки заявки на доступ.

Административные действия должны быть доступны только владельцу.

Интерфейс должен оставаться простым и не требовать от пользователей знания технических особенностей Codex.

### 2.6. Условия эксплуатации

- Бот и Codex работают на локальном компьютере владельца.
- Для использования бота не требуется выделенный сервер.
- Пользователи могут обращаться к боту удалённо через Telegram.
- При выключенном компьютере или недоступности Codex обработка запросов невозможна.
- Необходимо обеспечить корректное восстановление работы после перезапуска.
- Доступ через бота не должен предоставлять пользователям возможность произвольно управлять компьютером владельца.

## 3. Критерии приёмки MVP

Первая версия считается готовой, если:

- [ ] Бот работает локально и доступен через Telegram.
- [ ] Бот взаимодействует с Codex без отдельного OpenAI API.
- [ ] Пользователи могут отправлять сообщения и получать ответы.
- [ ] Поддерживаются Markdown и LaTeX.
- [ ] Длинные ответы отображаются полностью.
- [ ] Пользователь может сбросить контекст своего диалога.
- [ ] Контекст сохраняется после перезапуска приложения.
- [ ] Несколько разрешённых пользователей могут пользоваться ботом.
- [ ] Диалоги пользователей полностью изолированы друг от друга.
- [ ] Неавторизованные пользователи не могут пользоваться агентом.
- [ ] Администратор может одобрять, отклонять и отзывать доступ.
- [ ] Изменение юзернейма не нарушает систему авторизации.
- [ ] Ошибки обрабатываются без аварийного завершения приложения.
- [ ] Предоставлена инструкция по установке, настройке и запуску.

## 4. Дальнейшее развитие

Следующие возможности не входят в MVP и должны реализовываться отдельными этапами.

### Этап 2. Несколько диалогов и улучшение интерфейса

- Несколько независимых сессий для каждого пользователя.
- Организация диалогов через Telegram Topics.
- Создание, переименование и удаление диалогов.
- Сохранение отдельного контекста для каждой сессии.
- Потоковое отображение ответов.
- Остановка генерации ответа.
- Повторная генерация ответа.
- Возможность выбора модели.

### Этап 3. Работа с файлами

- Отправка изображений и скриншотов.
- Анализ фотографий заданий.
- Загрузка и изучение PDF, DOCX, XLSX и других документов.
- Работа с прикреплёнными учебными материалами.
- Создание готовых документов.
- Отправка пользователю результатов в виде файлов.

### Этап 4. Вычисления и визуализация

- Выполнение программного кода.
- Математические и статистические вычисления.
- Построение графиков функций.
- Создание диаграмм.
- Отправка графиков изображениями.
- Автоматическая проверка расчётов.
- Подготовка учебных работ с формулами, таблицами и графиками.

### Этап 5. Расширенные возможности

- Долгосрочная память агента.
- Поиск информации в интернете.
- Голосовые сообщения.
- Специализированные учебные режимы.
- Поиск по загруженным материалам.
- Персональные настройки поведения агента.
- Расширенное администрирование пользователей.
- Управление нагрузкой и ограничениями.

## 5. Общие требования к продукту

**Простота использования.** Пользователь должен взаимодействовать с ботом как с обычным AI-ассистентом, без необходимости разбираться во внутренней работе системы.

**Независимость пользователей.** Каждый пользователь имеет собственное изолированное пространство диалога.

**Надёжность.** Перезапуск приложения и временные ошибки не должны приводить к потере сохранённого контекста.

**Безопасность.** Только одобренные пользователи могут пользоваться агентом. Доступ к локальному компьютеру должен быть ограничен.

**Расширяемость.** Архитектура должна допускать добавление функциональности следующих этапов.

**Минимальная инфраструктура.** Продукт должен работать на компьютере владельца без обязательного использования внешнего сервера.

## 6. Границы текущих работ

В рамках первой версии необходимо реализовать только функциональность, описанную в разделе 2, и обеспечить выполнение критериев приёмки из раздела 3.

Возможности последующих этапов не должны разрабатываться заранее.

Конкретные технические решения, внутренняя архитектура, используемые библиотеки, хранение данных и способы интеграции с Codex определяются исполнителем в процессе отдельного обсуждения с заказчиком.

**Ожидаемый результат:** работающий приватный Telegram-бот на базе Codex с поддержкой нескольких одобренных пользователей, полностью независимыми диалогами, сохранением контекста, Markdown и LaTeX.
