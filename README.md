# Verfix Telegram Agent

Приватный Telegram-бот для общения с Codex через существующую ChatGPT-авторизацию. Каждая тема личного чата содержит отдельный сохранённый диалог, в том числе у одного пользователя. Бот работает одним локальным процессом на Linux и получает сообщения через long polling; публичный сервер и отдельный OpenAI API key не нужны.

## Темы и управление диалогами

Создавайте и переименовывайте темы штатными средствами Telegram, например «Работа» и «Учёба». Контекст, ожидающие фото и документы, последний ответ и выбранная владельцем модель принадлежат только текущей теме. Новая тема использует модель по умолчанию. Разные темы работают параллельно в пределах `MAX_CONCURRENT_REQUESTS`; второй запрос в занятой теме отклоняется, очереди нет. Все ответы и индикаторы работы остаются в исходной теме, даже если вы открыли другую.

- `/new` останавливает задание и очищает контекст и материалы текущей темы. Название темы и уже доставленные сообщения сохраняются.
- `/delete` запрашивает подтверждение, затем останавливает задание, удаляет тему с сообщениями из Telegram и очищает её данные у бота. «Отмена» сохраняет диалог; устаревшее подтверждение не действует.
- При частичном сбое удаления бот сохраняет незавершённую операцию и повторяет её после перезапуска. `/status` сообщает о незавершённых удалениях пользователя. Успешное полное удаление при ошибке не заявляется.
- Штатное удаление темы через интерфейс Telegram **не гарантирует немедленную очистку данных бота**: API не сообщает об удалении обычной темы. Для гарантированной очистки используйте `/delete`.
- Текст и вложения вне тем получают подсказку открыть или создать тему. `/help`, `/status` и административный `/users` доступны также вне тем; общего контекста там нет.

При первом запуске новой версии прежний диалог переносится в тему **«Предыдущий диалог»**. Сохраняются история, материалы, выбранная модель и недоставленные части ответа; уже доставленные сообщения остаются на прежнем месте и не копируются. Миграция SQLite выполняется транзакционно. Перед обновлением остановите старый процесс и сохраните резервную копию SQLite через SQLite backup API; запуск старой версии с новой схемой не поддерживается.

Если Telegram принял создание темы, но ответ API потерялся, бот сохраняет незавершённый перенос и не создаёт тему повторно при перезапуске. Служебное событие создания «Предыдущего диалога» завершает перенос, в том числе из накопленных обновлений. Если темы действительно нет, создайте её с этим именем вручную. Если тема уже есть, а служебное событие недоступно, сохранённый контекст остаётся в базе: не создавайте дубликат, требуется восстановить привязку к существующему ID темы. При явном отказе API следующая попытка обращения пользователя повторяет перенос.

## Подготовка Linux

Нужны Node.js **26.x**, npm, установленный Codex CLI с `app-server`, Python 3 с `venv`, `bubblewrap`, `libseccomp.so.2` и `prlimit`/`flock` из `util-linux`. Для Debian/Ubuntu:

```sh
sudo apt-get update
sudo apt-get install bubblewrap libseccomp2 util-linux python3 python3-venv
npm ci
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
codex --version
codex login
```

Проверено с Codex CLI **0.169.0**, Node.js **26.13.0** и Python **3.14.9**. Протокол динамических инструментов Codex экспериментальный; после обновления CLI проверяйте вычисления и границы доступа перед использованием.

При входе в Codex выберите ChatGPT. Авторизация выполняется локально владельцем; данные входа не отправляйте в Telegram. Инструкция установки CLI: [OpenAI Codex](https://github.com/openai/codex#quickstart). Подписка должна предоставлять доступ к выбранной модели. Наличие ChatGPT-входа не отменяет лимиты вашей подписки.

Изоляция требует разрешённых непривилегированных user namespaces в Linux. Если `bubblewrap` запрещён политиками системы, исправьте локальную настройку окружения: запуск команд без изоляции бот не использует. Временные рабочие каталоги не получают `.env`, SQLite, личные файлы или диалоги других пользователей. Python из `.venv` и его библиотеки доступны агенту внутри изоляции. Вычисления без сети; поиск по публичным страницам доступен через отдельный инструмент Codex.

## Настройка

В [BotFather](https://t.me/BotFather) создайте бота и получите токен. Включите **Threaded Mode** и разрешите пользователям управлять темами: опция **Disallow users to create new threads** должна быть выключена. Бот проверяет `getMe`: нужны `has_topics_enabled=true` и `allows_users_to_create_topics=true`; при неверной настройке запуск останавливается. [Описание тем Telegram](https://core.telegram.org/api/forum#bot-forums). Узнайте числовые Telegram ID владельца и пользователей. Скопируйте пример, заполните его локально:

```sh
cp .env.example .env
chmod 600 .env
```

```dotenv
TELEGRAM_BOT_TOKEN=123456:token_from_botfather
OWNER_TELEGRAM_ID=123456789
ALLOWED_USER_IDS=234567890,345678901
```

Владелец всегда имеет доступ; его не обязательно включать в `ALLOWED_USER_IDS`. Посторонним бот не отвечает, в том числе на `/start`, и не загружает их вложения. Используйте только личные чаты. Групповые сообщения не обрабатываются.

`.env` перечитывается автоматически. Изменяйте `ALLOWED_USER_IDS` для выдачи и отзыва доступа: отзыв сразу запрещает новые запросы и ещё не доставленные ответы. Диалог при этом сохраняется и продолжится после возврата доступа. При ошибке файла во время работы новые запросы и доставка приостанавливаются до исправления; владельцу доступен диагностический `/status`. Изменение токена, путей хранения и параметров запуска применяйте с перезапуском процесса.

| Параметр | Значение по умолчанию |
|---|---|
| `DATABASE_PATH` | `./runtime/bot.sqlite` |
| `RUNTIME_DIR` | `./runtime` |
| `MAX_CONCURRENT_REQUESTS` | `4` |
| `REQUEST_TIMEOUT_MS` | `900000` — 15 минут |
| `DIALOGUE_FILE_BYTES` | `500000000` — 500 МБ исходников и результатов на диалог |
| `POLL_TIMEOUT_SECONDS` | `30` |
| `CONFIG_RELOAD_INTERVAL_MS` | `500` |

Запускайте из корня проекта. `.env`, `.venv`, `runtime`, SQLite и логи исключены из Git. Каталог выполнения создаётся с правами `0700`, приватные файлы — `0600`. Не публикуйте токен, содержимое `.env`, базу или историю Codex. Для отдельной установки используйте собственные приватные пути хранения.

## Проверка и запуск

```sh
npm run check
npm test
npm run build
npm start
```

`npm test` проверяет Bot API через локальный HTTP-сервер и не отправляет настоящие сообщения в Telegram. Если конфигурация обязательных полей неверна, запуск завершится до обращения к Codex и Telegram. Одновременно может работать один процесс с данным `RUNTIME_DIR`; `flock` снимает блокировку и при аварийном завершении. Остановка — `Ctrl+C` или `SIGTERM`.

Для включения проверок настоящей вычислительной среды:

```sh
VERFIX_TEST_PYTHON="$PWD/.venv/bin/python" npm test
```

Если экземпляр запущен в фоне с PID-файлом `runtime/app.pid`, для остановки отправьте ему `SIGTERM`: `kill -- "$(cat runtime/app.pid)"`. После остановки можно снова выполнить `npm start`.

Для работы бот должен оставаться запущенным, а компьютер — включённым с доступом в интернет. После старта сообщения, накопленные во время простоя, не выполняются: в каждую затронутую тему одобренного пользователя отправляется одно уведомление с просьбой повторить запрос. Время Telegram имеет точность до секунды, поэтому сообщения из неоднозначной секунды запуска также пропускаются: окно составляет менее секунды. Новые сообщения после этой границы обрабатываются, в том числе после восстановления временно потерянного соединения.

## Команды

| Команда | Действие |
|---|---|
| `/start`, `/help` | Краткая справка |
| `/new` | Остановить задание и очистить контекст и материалы текущей темы |
| `/delete` | Удалить текущую тему и данные после подтверждения |
| `/text` | Полная читаемая текстовая версия последнего ответа |
| `/status` | Состояние своего запроса; владельцу — также диагностика бота и Codex |
| `/users` | Список доступа, только владельцу |
| `/model` | Выбор модели из каталога Codex и уровня рассуждения, только владельцу |

Для обычных пользователей фиксированы `gpt-6.1-sol` и `medium`. Владелец начинает с тех же значений; выбор через `/model` действует только на текущую тему и сохраняется после `/new` и перезапуска. Если выбранная модель недоступна, бот сообщает об ошибке и не подменяет её автоматически.

В одной теме одновременно выполняется один запрос. Следующее сообщение или вложение во время обработки не ставится в очередь: дождитесь ответа и повторите его. `/new` и подтверждённый `/delete` останавливают задание только этой темы. Общий предел задаётся `MAX_CONCURRENT_REQUESTS` (по умолчанию четыре одновременных запроса), остальные получают уведомление о занятости.

## Генерация изображений

Все одобренные пользователи могут попросить картинку обычным сообщением: «Нарисуй кота-космонавта», «Создай постер для книжного клуба». Модель вызывает встроенную генерацию изображений Codex, а бот отправляет готовые изображения и сопроводительный текст в текущую тему. Возможность доступна и в существующих диалогах; выполнять `/new` или менять модель для её включения не нужно.

Используется текущая ChatGPT-авторизация установленного Codex. Отдельный OpenAI API key не нужен. Генерация расходует доступные лимиты общего аккаунта владельца; доступность зависит от выбранной модели, подписки и ограничений провайдера, включая ограничения содержимого. При отказе или исчерпании лимита бот сообщает об этом и позволяет повторить запрос позже. Автоматического перехода на платный API нет.

Для работы по образцу пришлите изображение в текущий диалог и опишите желаемые изменения. Модель может использовать до пяти последних доступных изображений этого диалога. После `/new` образцы нужно прислать снова. Материалы других тем и пользователей, а также файлы компьютера владельца недоступны.

На один ответ допускается до четырёх изображений встроенной генерации в PNG: до 12 MB каждое, суммарно до 24 MB. Готовые изображения сохраняются для доставки; после перезапуска бот продолжает её без повторной генерации. Изображения, не подходящие для отправки как фото Telegram, передаются исходным PNG-файлом без изменения качества.

Для точных вычислений и графиков агент по-прежнему использует Python в изолированной среде. Художественные изображения создаются встроенной генерацией Codex.

## Файлы ответа

Результаты проверок реализации: [приёмка issue #13](docs/acceptance/issue-13-response-files.md).

Попросите «Создай PDF», «Сделай редактируемую презентацию PPTX», «Подготовь Excel с формулами» или другой формат, который агент способен создать. PDF должен содержать доступный для поиска текст, DOCX — редактируемый текст, XLSX — ячейки и формулы, PPTX — редактируемые элементы слайдов. Агент может включить таблицы, расчёты, графики и изображения текущего диалога. Художественные изображения создаются встроенным инструментом Codex.

Для среды документов установите и запустите Docker Engine, затем из корня проекта выполните:

```sh
docker build -t verfix-files:1 -f src/files/Dockerfile src/files
```

Учётная запись запуска бота должна иметь доступ к локальному Docker daemon. Этот доступ используется только доверенным кодом запуска; Docker-сокет агенту не передаётся. Образ содержит LibreOffice, Python и библиотеки python-docx, openpyxl, python-pptx, reportlab, pypdf, matplotlib, numpy, sympy, Pillow, requests. Агент может запускать программы и устанавливать дополнительные библиотеки в рабочее пространство задания. Сборка требует интернета и места для образа. При отсутствии Docker или образа бот сообщает о недоступности среды, продолжая обычное общение.

Каждое задание использует отдельный контейнер без прямой сети, с файловой системой образа только для чтения и ограничениями ресурсов (1 ГБ памяти, 1 CPU, 128 процессов, 640 МиБ рабочего tmpfs и 128 МиБ временного). Публичный HTTP(S) доступен через прокси, который блокирует локальные адреса и разрешает только порты 80/443. Каталог проекта, `.env`, авторизация Codex и чужие материалы внутрь не подключаются. Среда удаляется при завершении; при аварийном выходе бота watchdog завершает её после исчезновения прокси. Неэкспортированные промежуточные файлы не сохраняются.

На задание допускается до **10 файлов ответа**, каждый до **50 МБ** (50 000 000 байт). Исходники, файлы ответа и сохранённые изображения текущего диалога занимают вместе до **500 МБ на один топик**; владелец меняет квоту через `DIALOGUE_FILE_BYTES`. При заполнении старые материалы сохраняются, бот предлагает `/new`. На входе остаётся ограничение cloud Telegram `getFile`: **20 МБ на новый файл**. Для редактирования уже сохранённого результата до 50 МБ повторная загрузка из Telegram не нужна.

Отправьте документ с просьбой изменить его либо попросите доработать предыдущий результат. Исходники и файлы ответа доступны только текущему топику, в том числе изолированы от других тем того же пользователя. Они переживают перезапуск, удаляются через `/new` или подтверждённый `/delete`; файлы других тем сохраняются. Готовые экспортированные файлы сохраняются до доставки; при ошибке одного результата, таймауте или перезапуске готовая часть отправляется с пояснением. Подтверждённые Telegram части не повторяются. Если процесс завершился между отправкой и записью подтверждения, возможна повторная доставка этой части, как и для текстовых ответов. Отзыв доступа останавливает доставку.

Проверки настоящей среды документов включаются отдельно:

```sh
VERFIX_TEST_FILES=1 node --test tests/files tests/engine/engine.test.ts
```

## Фото и документы

Отправьте фото, скриншоты или файлы, затем напишите задание отдельным сообщением. Вложения без задания ожидают его и сохраняются при перезапуске. Можно сразу написать задание в подписи: бот передаст материалы вместе с ней. Фотографии Telegram-альбома собираются в одно задание, сохраняя порядок; подпись относится ко всему альбому. Для нескольких отдельных файлов сначала отправьте все материалы без подписи, затем текст задания.

Поддерживаются JPEG, PNG и WebP, в том числе изображения, отправленные как документы; PDF с текстом или сканами; DOCX, XLSX и PPTX; текстовые UTF-8 файлы, включая TXT, Markdown, CSV, JSON и распространённые исходные коды. Из PDF передаются полный извлечённый текст и изображения всех страниц. Из DOCX читаются абзацы, таблицы, колонтитулы, сноски и встроенные изображения; простые формулы Office Math с дробями, степенями, индексами и корнями передаются в LaTeX. Более сложные формулы передаются целиком как явно помеченный структурированный OMML XML, сохраняя операторы, свойства и вложенность. Из XLSX читаются ячейки всех листов, текст, сохранённые значения и формулы без их выполнения, встроенные изображения; из PPTX — текст и таблицы слайдов в порядке презентации, заметки и встроенные изображения. Исходная вёрстка Office не воспроизводится.

Диаграммы Office, SmartArt, векторные рисунки Word, фигуры Excel, соединители, группы и сложные фигуры PowerPoint не поддерживаются. Презентации с текстом, изображениями или фигурами в макетах и образцах слайдов также требуют экспорта: для точного визуального анализа лучше **экспортировать документ в PDF**, где видимое содержимое будет передано изображениями страниц. Такие объекты проверяются и в связанных частях документа. Для них вместо неполного извлечения агент получает явное указание изучить сохранённый исходник инструментами среды документов. Это позволяет дорабатывать документ; если конкретные элементы сохранить невозможно, агент должен объяснить потери. Для заданий, зависящих от расположения объектов или оформления, также отправляйте PDF. Пароли, макросы, встроенные объекты и анимированные изображения не поддерживаются. Внешние ссылки из документов не загружаются.

| Ограничение | Предел |
|---|---|
| Вложения в одном задании | 10 |
| Исходный файл / все исходные файлы задания | 20 MB / 50 MB |
| Страницы PDF | Без ограничения по количеству; действуют ограничения объёма и ресурсов обработки |
| Подготовленные изображения на задание | Суммарно 6 MB; размер нормализуется до 2048 px по длинной стороне |
| Извлечённый текст на задание | 500 kB в UTF-8 |
| Сохранённый контекст материалов диалога | 12 MB с учётом base64 и текста |
| Распаковка одного Office-файла | 50 MB, до 2000 элементов, до 20 MB на элемент, коэффициент сжатия до 200 |

При превышении лимита бот просит разделить материалы или начать новый диалог через `/new`; содержимое не усекается молча. Неподдерживаемый или повреждённый файл получает понятную ошибку. Для просмотра изображений выбранная модель должна поддерживать image input; бот не подменяет модель и не заменяет изображение текстовым описанием.

Документы распаковываются, читаются и изображения декодируются внутри изолированной среды без сети и доступа к личным файлам владельца. Исходные байты сохраняются в SQLite своего диалога до `/new`, чтобы агент мог редактировать документы с сохранением поддерживаемого оформления. Они входят в общую квоту файлов диалога. Подготовленные текст и изображения остаются в контексте только диалога отправителя, доступны для уточнений после перезапуска и удаляются при `/new`. Имена файлов являются подписями материалов и не дают агенту доступ к путям компьютера.

Ответы поддерживают заголовки, таблицы и LaTeX через [Telegram rich messages](https://core.telegram.org/bots/api#rich-message-formatting-options). Длинные ответы разделяются без усечения; код, таблицы и формулы сохраняются целиком в читаемой текстовой форме, если они не помещаются в одну оформленную часть. При неподдерживаемом rich-формате бот отправляет обычный текст; `/text` также всегда доступен. Вид оформленного ответа зависит от версии Telegram-клиента.

Созданные агентом изображения и PNG-графики отправляются в чат вместе с объяснением. Изображение, превышающее ограничения `sendPhoto` по размеру или пропорциям, передаётся как PNG-файл через `sendDocument`, без изменения изображения. Файлы ответа произвольных форматов создаются в отдельной среде документов и передаются через `sendDocument`.

При тайм-ауте, недоступности Codex или ошибке вычислений приходит понятное сообщение. После прерывания процесса незавершённый запрос не запускается повторно автоматически: бот предлагает повторить его, сохраняя предыдущий контекст. Готовый сохранённый ответ продолжает доставляться; подтверждённые части не повторяются. Если процесс завершился между отправкой части и сохранением подтверждения Telegram, эта часть может прийти повторно.

Требования и границы доступа описаны в [issue #1](https://github.com/verf1x/verfix-telegram-agent/issues/1), [issue #6: входящие вложения](https://github.com/verf1x/verfix-telegram-agent/issues/6) и [issue #10: генерация изображений](https://github.com/verf1x/verfix-telegram-agent/issues/10) и [issue #13: файлы ответа](https://github.com/verf1x/verfix-telegram-agent/issues/13), доменные термины — в [GLOSSARY.md](GLOSSARY.md), решение об изоляции — в [ADR 0001](docs/adr/0001-isolated-computations.md). Загрузка файлов следует [Telegram getFile](https://core.telegram.org/bots/api#getfile), изображения передаются как native image input [Codex app-server](https://developers.openai.com/codex/app-server).
