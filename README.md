# Verfix Telegram Agent

Приватный Telegram-бот для общения с Codex через существующую ChatGPT-авторизацию. У каждого одобренного пользователя свой сохранённый диалог. Бот работает одним локальным процессом на Linux и получает сообщения через long polling; публичный сервер и отдельный OpenAI API key не нужны.

## Подготовка Linux

Нужны Node.js **26.x**, npm, установленный Codex CLI с `app-server`, Python 3 с `venv`, `bubblewrap`, `libseccomp.so.2` и `prlimit`/`flock` из `util-linux`. Для Debian/Ubuntu:

```sh
sudo apt-get update
sudo apt-get install bubblewrap libseccomp2 util-linux python3 python3-venv
npm ci
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
codex --version
codex login
```

Проверено с Codex CLI **0.167.2**, Node.js **26.13.0** и Python **3.14.9**. Протокол динамических инструментов Codex экспериментальный; после обновления CLI проверяйте вычисления и границы доступа перед использованием.

При входе в Codex выберите ChatGPT. Авторизация выполняется локально владельцем; данные входа не отправляйте в Telegram. Инструкция установки CLI: [OpenAI Codex](https://github.com/openai/codex#quickstart). Подписка должна предоставлять доступ к выбранной модели. Наличие ChatGPT-входа не отменяет лимиты вашей подписки.

Изоляция требует разрешённых непривилегированных user namespaces в Linux. Если `bubblewrap` запрещён политиками системы, исправьте локальную настройку окружения: запуск команд без изоляции бот не использует. Временные рабочие каталоги не получают `.env`, SQLite, личные файлы или диалоги других пользователей. Python из `.venv` и его библиотеки доступны агенту внутри изоляции. Вычисления без сети; поиск по публичным страницам доступен через отдельный инструмент Codex.

## Настройка

В [BotFather](https://t.me/BotFather) создайте бота и получите токен. Узнайте числовые Telegram ID владельца и пользователей. Скопируйте пример, заполните его локально:

```sh
cp .env.example .env
chmod 600 .env
```

```dotenv
TELEGRAM_BOT_TOKEN=123456:token_from_botfather
OWNER_TELEGRAM_ID=123456789
ALLOWED_USER_IDS=234567890,345678901
```

Владелец всегда имеет доступ; его не обязательно включать в `ALLOWED_USER_IDS`. Посторонним бот не отвечает, в том числе на `/start`, и не загружает их вложения. Используйте только личные чаты. Групповые сообщения не обрабатываются.

`.env` перечитывается автоматически. Изменяйте `ALLOWED_USER_IDS` для выдачи и отзыва доступа: отзыв сразу запрещает новые запросы и ещё не доставленные ответы. Диалог при этом сохраняется и продолжится после возврата доступа. При ошибке файла во время работы новые запросы и доставка приостанавливаются до исправления; владельцу доступен диагностический `/status`. Изменение токена, путей хранения и параметров запуска применяйте с перезапуском процесса.

| Параметр | Значение по умолчанию |
|---|---|
| `DATABASE_PATH` | `./runtime/bot.sqlite` |
| `RUNTIME_DIR` | `./runtime` |
| `MAX_CONCURRENT_REQUESTS` | `4` |
| `REQUEST_TIMEOUT_MS` | `600000` — 10 минут |
| `POLL_TIMEOUT_SECONDS` | `30` |
| `CONFIG_RELOAD_INTERVAL_MS` | `500` |

Запускайте из корня проекта. `.env`, `.venv`, `runtime`, SQLite и логи исключены из Git. Каталог выполнения создаётся с правами `0700`, приватные файлы — `0600`. Не публикуйте токен, содержимое `.env`, базу или историю Codex. Для отдельной установки используйте собственные приватные пути хранения.

## Проверка и запуск

```sh
npm run check
npm test
npm run build
npm start
```

`npm test` проверяет Bot API через локальный HTTP-сервер и не отправляет настоящие сообщения в Telegram. Если конфигурация обязательных полей неверна, запуск завершится до обращения к Codex и Telegram. Одновременно может работать один процесс с данным `RUNTIME_DIR`; `flock` снимает блокировку и при аварийном завершении. Остановка — `Ctrl+C` или `SIGTERM`.

Для включения проверок настоящей вычислительной среды:

```sh
VERFIX_TEST_PYTHON="$PWD/.venv/bin/python" npm test
```

Если экземпляр запущен в фоне с PID-файлом `runtime/app.pid`, для остановки отправьте ему `SIGTERM`: `kill -- "$(cat runtime/app.pid)"`. После остановки можно снова выполнить `npm start`.

Для работы бот должен оставаться запущенным, а компьютер — включённым с доступом в интернет. После старта сообщения, накопленные во время простоя, не выполняются: каждому одобренному пользователю с такими сообщениями отправляется одно уведомление с просьбой повторить запрос. Время Telegram имеет точность до секунды, поэтому сообщения из неоднозначной секунды запуска также пропускаются: окно составляет менее секунды. Новые сообщения после этой границы обрабатываются, в том числе после восстановления временно потерянного соединения.

## Команды

| Команда | Действие |
|---|---|
| `/start`, `/help` | Краткая справка |
| `/new` | Удалить сохранённый контекст и начать новый диалог |
| `/text` | Полная читаемая текстовая версия последнего ответа |
| `/status` | Состояние своего запроса; владельцу — также диагностика бота и Codex |
| `/users` | Список доступа, только владельцу |
| `/model` | Выбор модели из каталога Codex и уровня рассуждения, только владельцу |

Для обычных пользователей фиксированы `gpt-6.1-sol` и `medium`. Владелец начинает с тех же значений; выбор через `/model` сохраняется после `/new` и перезапуска. Если выбранная модель недоступна, бот сообщает об ошибке и не подменяет её автоматически.

У пользователя одновременно выполняется один запрос. Следующее сообщение или вложение во время обработки не ставится в очередь: дождитесь ответа и повторите его. `/new` также требует завершения текущего запроса. Общий предел задаётся `MAX_CONCURRENT_REQUESTS` (по умолчанию четыре одновременных запроса), остальные получают уведомление о занятости.

## Фото и документы

Отправьте фото, скриншоты или файлы, затем напишите задание отдельным сообщением. Вложения без задания ожидают его и сохраняются при перезапуске. Можно сразу написать задание в подписи: бот передаст материалы вместе с ней. Фотографии Telegram-альбома собираются в одно задание, сохраняя порядок; подпись относится ко всему альбому. Для нескольких отдельных файлов сначала отправьте все материалы без подписи, затем текст задания.

Поддерживаются JPEG, PNG и WebP, в том числе изображения, отправленные как документы; PDF с текстом или сканами; DOCX, XLSX и PPTX; текстовые UTF-8 файлы, включая TXT, Markdown, CSV, JSON и распространённые исходные коды. Из PDF передаются полный извлечённый текст и изображения всех страниц, из Office — текст/ячейки/слайды и поддерживаемые встроенные изображения. Пароли, макросы, встроенные объекты и анимированные изображения не поддерживаются. Внешние ссылки из документов не загружаются.

| Ограничение | Предел |
|---|---|
| Вложения в одном задании | 10 |
| Исходный файл / все исходные файлы задания | 20 MB / 50 MB |
| Страницы PDF | 20 |
| Подготовленные изображения на задание | 20, суммарно 6 MB; размер нормализуется до 2048 px по длинной стороне |
| Извлечённый текст на задание | 500 kB в UTF-8 |
| Сохранённый контекст материалов диалога | 12 MB с учётом base64 и текста, до 20 изображений |
| Распаковка одного Office-файла | 50 MB, до 2000 элементов, до 20 MB на элемент, коэффициент сжатия до 200 |

При превышении лимита бот просит разделить материалы или начать новый диалог через `/new`; содержимое не усекается молча. Неподдерживаемый или повреждённый файл получает понятную ошибку. Для просмотра изображений выбранная модель должна поддерживать image input; бот не подменяет модель и не заменяет изображение текстовым описанием.

Документы распаковываются, читаются и изображения декодируются внутри изолированной среды без сети и доступа к личным файлам владельца. Исходные байты используются временно при подготовке и не сохраняются в SQLite. Подготовленные текст и изображения остаются в контексте только диалога отправителя, доступны для уточнений после перезапуска и удаляются при `/new`. Имена файлов являются подписями материалов и не дают агенту доступ к путям компьютера.

Ответы поддерживают заголовки, таблицы и LaTeX через [Telegram rich messages](https://core.telegram.org/bots/api#rich-message-formatting-options). Длинные ответы разделяются без усечения; код, таблицы и формулы сохраняются целиком в читаемой текстовой форме, если они не помещаются в одну оформленную часть. При неподдерживаемом rich-формате бот отправляет обычный текст; `/text` также всегда доступен. Вид оформленного ответа зависит от версии Telegram-клиента.

Созданные агентом PNG-графики отправляются в чат вместе с объяснением. Изображение, превышающее ограничения `sendPhoto` по размеру или пропорциям, передаётся как PNG-файл через `sendDocument`, без изменения изображения. Создание произвольных документов не поддерживается.

При тайм-ауте, недоступности Codex или ошибке вычислений приходит понятное сообщение. После прерывания процесса незавершённый запрос не запускается повторно автоматически: бот предлагает повторить его, сохраняя предыдущий контекст. Готовый сохранённый ответ продолжает доставляться; подтверждённые части не повторяются. Если процесс завершился между отправкой части и сохранением подтверждения Telegram, эта часть может прийти повторно.

Требования и границы доступа описаны в [issue #1](https://github.com/verf1x/verfix-telegram-agent/issues/1) и [issue #6: входящие вложения](https://github.com/verf1x/verfix-telegram-agent/issues/6), доменные термины — в [GLOSSARY.md](GLOSSARY.md), решение об изоляции — в [ADR 0001](docs/adr/0001-isolated-computations.md). Загрузка файлов следует [Telegram getFile](https://core.telegram.org/bots/api#getfile), изображения передаются как native image input [Codex app-server](https://developers.openai.com/codex/app-server).
