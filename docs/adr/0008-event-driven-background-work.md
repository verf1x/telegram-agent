# Фоновые операции запускаются по событию или сроку

В простое Verfix разбирал полную историю всех диалогов каждые 250 мс, поэтому нагрузка росла с размером истории. Бот хранит компактные индексируемые метаданные фоновых операций в текущей SQLite и обновляет их одной транзакцией с состоянием диалога или рассылки. В одном процессе обработчик просыпается при запуске, после сохранения новой работы или по одному таймеру на ближайший срок. [Задача №34](https://github.com/verf1x/telegram-agent/issues/34) · [Исследование вариантов](../research/issue-34-bot-scheduling.md)

Если состояние одного диалога не читается, бот сохраняет запись, один раз сообщает об ошибке без содержимого диалога и продолжает операции других топиков. Работу затронутого топика можно возобновить после исправления записи.

Бот читает `.env` при запуске. Изменения списка доступа применяются при следующем запуске до возобновления доставки.
