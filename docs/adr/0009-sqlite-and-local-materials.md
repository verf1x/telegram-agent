# SQLite хранит состояние, локальный каталог хранит байты файлов

Verfix оставляет SQLite и хранит байты материалов в закрытом каталоге рядом с базой. На стенде каталог снизил p95 короткого ответа с 1,61 до 0,69 с при трёх соседних записях по 50 МБ. В сравнении с одинаковым каталогом при четырёх текстовых заданиях p95 был 117 мс у SQLite и 124 мс у PostgreSQL. [Замеры #37](../research/issue-37-storage-benchmark.md) · [Решение о файлах #29](https://github.com/verf1x/telegram-agent/issues/29) · [Решение о БД #31](https://github.com/verf1x/telegram-agent/issues/31)

SQLite хранит привязку файла к пользователю и топику, размер для квоты и ссылку на байты. Бот подтверждает ссылку после синхронизации файла и каталога с диском. При очистке диалога SQLite сохраняет список файлов для удаления, чтобы бот завершил очистку после сбоя. Перед первым запуском сохраняем копию базы с BLOB. После перехода база и каталог составляют один комплект для резервного копирования. Удаление файла освобождает запись каталога и сохраняет правила доступа из ADR 0004 и 0006. Физическая очистка зависит от накопителя и срока хранения резервных копий.
