# Проверка независимых личных топиков — issue #15

Дата: 2026-11-13. Спецификация: [issue #15](https://github.com/verf1x/verfix-telegram-agent/issues/15), решение: [ADR 0006](../adr/0006-private-topics-and-deletion.md).

## Автоматические проверки

Проверки выполнены через публичные границы бота, SQLite, движка и HTTP-транспорта Telegram:

- Параллельные задания в разных темах одного пользователя; отдельная занятость темы и общий предел нагрузки без очереди.
- Раздельные история, native UUID, подготовленные материалы, ожидающие вложения, альбомы, модель владельца и доставка после перезапуска. Доступ обычного пользователя к смене модели не расширен.
- Проверка владельца native-контекста по пользователю и топику: чужой UUID отвергается, legacy-контекст привязывается однократно.
- Текст, rich fallback, PNG, PNG как документ и typing сохраняют `message_thread_id`. Ошибка темы не меняет адрес доставки.
- `/new` и подтверждённый `/delete` отменяют работу, включая доставку. Поздние результаты не восстанавливают контекст и не запускают оставшиеся отправки.
- Создание native-файлов начинается только после сохранения принадлежности UUID. Отменённое выделение контекста не оставляет файлов. Неудачно удалённые контексты ошибочных запросов остаются учтены для следующего сброса или удаления.
- Подтверждение удаления привязано к пользователю, теме и сроку действия. Проверены отмена, повторное нажатие, другая тема/пользователь, истечение срока, перезапуск и завершение параллельной миграции/очистки.
- Частичный сбой удаления сохраняется и повторяется после перезапуска. Полный успех при ошибке не заявляется.
- Миграция SQLite сохраняет старую историю, материалы, модель и outbox. Потерянный ответ создания темы не вызывает повторное создание при перезапуске; служебное событие завершает перенос, включая накопленные обновления.
- Текст вне тем не создаёт общего диалога. Штатные события создания и переименования тем не запускают Codex.

Итог полного прогона: **151/151 тестов**, без ошибок и пропусков, включая реальную обработку документов и вычисления в sandbox. Проверка типов, сборка и `git diff --check` прошли. Два независимых ревью (стандарты и спецификация) завершены; найденные гонки исправлены и покрыты регрессионными тестами.

Команды проверки:

```sh

npm run check
npm run build
git diff --check
```

## Проверка настоящего бота

`getMe` подтвердил для `@verfix_agent` включённые `has_topics_enabled` и `allows_users_to_create_topics`. Перед изменением схемы рабочий процесс остановлен и создана резервная копия через SQLite backup API. Шесть существовавших диалогов перенесены в темы без оставшихся legacy-записей или незавершённой привязки; старые сообщения в Telegram не копировались.

Пользователь в Telegram подтвердил появление «Предыдущего диалога», штатное создание тем «Работа» и «Учёба» и получение ответов в обеих. После предложения проверить прежний контекст, независимость тем, `/new` и отмену/подтверждение `/delete` пользователь сообщил: «все работает».

Дополнительно проведён контролируемый интеграционный прогон в двух временных темах владельца: настоящий Telegram API, настоящий Codex и изолированные вычисления, отдельные временные SQLite и runtime. Входящие updates формировались тестовым драйвером; реальные нажатия пользователя этим прогоном не имитировались. Подтверждены:

- Два параллельных обращения с разными контрольными фактами и native UUID.
- Продолжение после закрытия и повторного открытия бота, SQLite и движка: каждая тема называет свой контрольный факт и не называет факт соседней.
- Доставка объяснения, PNG научного графика и индикаторов работы в исходную тему.
- Сброс только выбранной темы и подсказка на текст вне тем.
- Реальное удаление тестовых тем через путь подтверждения бота и очистка их SQLite/native-контекстов. Временные темы и файлы удалены после прогона.

Итог интеграционного драйвера: 6 проверок прошли, доставлено 9 частей ответа, в том числе 3 PNG. Дополнительная ручная проверка со вторым аккаунтом в этой сессии не проводилась; межпользовательская изоляция проверена автоматическими тестами движка и бота. Художественная генерация отдельно заново не запускалась; маршрутизация проверена на PNG реального isolated_compute и native image fixtures.

## Ограничения Telegram

[Bot API](https://core.telegram.org/bots/api#update) не присылает уведомления о штатном удалении обычной темы пользователем. Гарантированный путь очистки — `/delete`.

`createForumTopic` не предоставляет ключа идемпотентности. При неизвестном исходе запроса бот оставляет сохранённую миграцию и не создаёт дубликат. Если тема отсутствует, пользователь может создать «Предыдущий диалог» вручную; её событие завершит перенос. Если тема уже есть, а ответ и служебное событие утрачены, нужна операторская привязка к существующему ID темы. История и материалы остаются в SQLite. Эта граница и порядок восстановления описаны в README.
